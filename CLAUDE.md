# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

- Before making any updates, cut a new branch from an up-to-date `stage` (`git checkout stage && git pull && git checkout -b <type>/<short-name>`). Never commit directly to `stage` or `main`; PRs target `stage`.

- when working on a 'feature' from the `_features.md` list, check off the tasks as you complete them.
- After adding or changing a feature, run a quick browser smoke test before calling it done: open it on the local stack (`npm run dev:local`, sign in with the matching test account), click through its buttons, menus, dialogs and forms, and read the browser console and failed network requests. Fix any warning or error the app causes; name any that come from outside the app (browser extensions, an expired session) instead of chasing them. Headless Playwright is fine when the MCP browsers are busy.
- Run the ui-ux-reviewer only after major UI changes (layout changes, new components or pages), not after every sprint of updates

## Commands

```bash
npm run dev          # Start dev server (http://localhost:3000) against .env.local (the hosted project)
npm run dev:local    # Local testing: starts the local Supabase stack, seeds test accounts, serves http://localhost:3100
npm run dev:seed     # Re-seed the local test accounts and "Test Table" (`-- --reset` rebuilds the hero's sheet)
npm run build        # Production build (nuxt build)
npm run generate     # Static site generation (nuxt generate)
npm run type-check   # TypeScript check (nuxt typecheck)
npm run lint         # Run oxlint then eslint sequentially, both with --fix
npm run format       # Prettier format all files
npm run test         # Vitest: utils, Nimble data integrity, golden level tables
npm run preview      # Preview production build locally
```

> Requires Node.js `^20.19.0 || >=22.12.0`. Use `nvm use 22.18.0` if needed.

## Stack

"Lantern": Vue 3 + Nuxt 3 (SPA mode, `ssr: false`) + TypeScript + Pinia + Supabase (auth, Postgres, storage, realtime). No UI library: custom components styled with SCSS and CSS variables. Hosted on Vercel.

## Design

`design/` is the reference (not wired into the app): `README.md` lists every screen, `screens/*.dc.html` hold exact markup and interaction logic, `tokens.json` the theme values. Match it when changing UI.

Reconfigure (beside Edit sheet) goes back to a chosen level the same way, then reopens `LevelUpDialog` one level at a time up to the old level with that level's recorded picks (`previous`) filled in; cancelling a step puts the whole sheet back as it was. PF2e level-ups record their picks too (`LevelHistoryEntry.pf2e`) and replay the same way; redoing PF2e level 1 isn't offered (the builder's steps live in its page). `tests/pf2eData.test.ts` checks integrity. The deity lists on weapons and spells, legacy (OGL) entries, entries AoN marks superseded and duplicate reprints are left out, and so are sections whose lead names a closed book (`withoutLegacy`, `leadNamesClosed`, `withoutClosedMentions` in `scripts/lib/aon.ts`), closed archetypes' dedications in prerequisites (`withoutClosedDedications`; a feat needing only one goes) and Pathfinder Society notes; the run fails if a closed title (`closedTitlesIn`) would be written, and writes the closed titles to `tests/fixtures/pf2e/closed-books.json` for the data test; what AoN's entry leaves blank (druidic orders' mechanics, Awakened Animal's Hit Points) is a `gap` note, never guessed; a background's skills also come from its "You're trained in…" text (`backgroundSkillText` in `scripts/lib/aon.ts`): `skillChoices` for "your choice of…" (no options = any skill), `deitySkill` for Raised by Belief, and Lores the player names as prose entries in `skills`
- `data/pf2e/effects.ts`, `utils/pf2eEffects.ts` — structured effects for PF2e abilities (`Pf2eEffectDef` in `data/pf2e/types.ts`): hand-written from each ability's rules text, cited, with what the kinds can't say left in `note`. Modes: `permanent` (on whenever the hero has the ability, matched by the names of their feats, class features, picks and spells), `toggle` (the hero turns it on: Rage, with temp HP of level + CON that go when it ends, and it ends when the hero falls unconscious, `endOnUnconscious`; Courageous Anthem) and `given` (an ally's effect: Bless, Heroism +1/+2/+3, Courageous and Rallying Anthem, Enlarge, Haste, Guidance). Kinds: `modifier` (selectors ac, attack, damage, perception, saves, skills, checks, speed; `melee`, `agileHalf` for Rage, `weapons: 'agileFinesse'` and `byLevel` for Precise Strike, `skills` for Outwit), `damageDice` (Sneak Attack on an off-guard target with agile, finesse or ranged attacks, the Precision edge on the first hit on hunted prey, Strategic Strike with Devise a Stratagem; dice by level), `map` (the Flurry edge's −3/−6, agile −2/−4), `damageAttribute` (Thief: DEX to finesse melee damage), `specialization` (weapon specialization by the Strike's rank; the greater one replaces it), `condition` (Enlarge's clumsy 1, Haste's quickened, merged into `activeConditions` / `conditionValue`), `dexCap` (Mountain Stance, whose item bonus is `cumulativeWith` Mystic Armor's), `tempHp` (a formula or the cast rank's value: False Vitality), `deathAt` (Diehard), `recoveryDc` (Toughness), `degree` (a save's degree upgraded: Juggernaut's success → critical success; ones `against` some effects, Bravery's fear, come back as notes from `shiftedDegree`), `proficiency` (a rank a feature raises a statistic to: Fortitude master adds +2 over the sheet's expert, `effectiveRank` also feeds weapon specialization), `resistance` (`resistancesNow`, shown beside Speed: Guardian's Armor 1 + ½ level, Raging Resistance 3 + CON with Rage), `fistDie` (Powerful Fist's d6). `modifier` also takes selector `initiative` (Incredible Initiative, Foresight; rolled by the turn tracker) and `actions` (a bonus only to that action's check, rolled from the Actions panel: Clinging Shadows Stance to Grapple); `damageDice` also `when: 'always'` and `weapons: 'unarmed'` (Weapon Surge, Qi Form, Inner Upheaval). A toggle can say when it `ends` (`startOfTurn`, `endOfTurn`, `endOfNextTurn`, `trigger`, `minute`, `encounter`; `endPf2eEffects`, run by the turn steps, ends given ones too) and keep its cast rank's number (`toggleEffect`'s `value`, `sheet.effects.values`: Competitive Edge +2 at 7th). Abilities without a written entry get one read from their text (`derivedEffects`: unconditional bonuses, resistances, proficiency increases, degree upgrades and Speed are `permanent`; a bonus that comes with a use or holds only sometimes is a toggle whose note is its sentence; a bonus to something the sheet doesn't roll is a note; a barbarian instinct's Rage damage requires Rage); a written entry always wins (`pf2eEffectDef`). Third wave of written ones: Incredible Movement and Panache Speed by level, Raging Resistance, Guardian's Armor, Arcane Cascade; fourth: self and ally spells (Protection, Runic Weapon/Body, Weapon Surge, Fire Shield, Stoke the Heart, Song of Strength, Inner Upheaval, Qi Form, the monk stances, Competitive Edge, Magic's Vessel, Untamed Form, Touch of the Moon, Soothing Words, Blood Ward, Foresight, Fly, Invisibility, Blur, False Vitality, Sure Strike; a champion's Lay on Hands and Shields of the Spirit as `(ally)` effects since they don't help the caster). An effect can `require` a toggle (the ranger's edges, Precision included, need Hunt Prey); their notes show while it's on (Flurry and Outwit count only against the prey). A raised shield is a +2 circumstance bonus in the same stacking, so the Shield spell's +1 doesn't add to it. `adjusted` in `utils/pf2ePlay.ts` stacks effect modifiers with conditions (by type), `deathAt`, `recoveryDc` and `recoveryCheck` read Diehard and Toughness, and `speedNow` adds Fleet. The sheet's `components/pf2e/SheetEffects.vue` holds the hero's toggles, what's always on, and effects from allies; the Strikes panel offers "Target off-guard", "First hit on your prey this round" and "Devise a Stratagem" (for the next Strike only: INT to the attack when it's at least the usual attribute, with agile, finesse or non-thrown ranged weapons, `stratagemUsesInt`; that Strike's damage keeps strategic strike's dice until rolled, `stratagemAttacked` / `stratagemDamaged`) when the hero has those dice; Strikes record their proficiency `rank`, and adds them to damage (doubled on a crit). Built feats record `id`, `frequency` and `trigger`, and class features their action (the action they embed, or the feat they grant). Fifth wave (`has` names the ability an entry needs when its name isn't one, with its kind when names repeat: the Elemental instinct vs the Elemental bloodline): a barbarian instinct's Rage damage as `<Instinct> (Rage damage)` (Fury, Superstition, Elemental, Bloodrager always; Dragon, Spirit and Giant are toggles for the choice made when raging; Animal only on unarmed attacks, `weapons: 'unarmed'`), which replace the text reader's `rageDamage`; the swashbuckler's brief panache; the champion's Selfish Shield (resistance against the triggering damage, ends `trigger`, its value set on use) and the `(Strikes)` spirit damage of Selfish Shield, Destructive Vengeance and Iron Command; each bloodline's blood magic on the sorcerer. `resistancesNow` takes a toggle's value when it has one. `tests/pf2eEffects.test.ts` (also checks every effect names an ability in the data, or its `has`), `tests/pf2eSpellEffects.test.ts`

- `utils/pf2eSpells.ts` — PF2e spellcasting on the sheet (Player Core pp. 297–303): `spellNumbers` (spell attack and DC after conditions), `heightenedRank` (cantrips and focus spells at half the level, rounded up), `castSpontaneous` (a slot of the spell's rank or higher, heightening it), `castPrepared` (that slot's spell, once), `castFont` (a cleric's divine font, 4/5/6 slots at the highest rank, p. 108), `castCantrip`, `castFocus` (1 Focus Point; focus cantrips are free) and `refocus`, `dailyPreparations`, `slotsFor` / `setSlotMax`, `focusPoolMax` (focus spells that cost a point, up to 3), and the DC 5 + stupefied flat check on every cast (p. 446); `castWentOff` tells a cast that spent its slot from one that didn't, `castEffect` rolls what the spell does at the rank it went off (spell attack less MAP and spell DC, or `focusNumbers` from the class DC for heroes with focus spells only) and turns on a spell's effect when it only ever affects the caster, `effectOnSelf` when the hero casts a buff on themselves. The builder's Spells step (`spellcastingPlan`: tradition from the class or its bloodline, patron or eidolon, picked by the player when that choice names none (`traditionChoice`, `creation.tradition`: a draconic bloodline, a dragon eidolon), the 1st-level spells-per-day row found by level, the spell attribute from the class text (`spellAttribute`: a magus uses INT), the focus pool from "focus pool of N" (`focusPool`: a psychic's 2) and a "Choose either…" devotion spell (`focusChoice`, within the deity's font), spontaneous when the class has a spell repertoire, counts from the spells-per-day table; `spellOptions`; `focusSpellOptions` with `creationFocusSpells` pre-selecting the focus spells and class cantrips the level 1 text names; the divine font when a deity offers both). `tests/pf2eSpells.test.ts`

- `utils/pf2ePlay.ts` — Pathfinder 2e table rules for the sheet. `degreeOf` (Player Core p. 401: ±10 from the DC, a natural 20 or 1 moves one degree); `stackMods` (p. 400: per type only the best bonus and worst penalty, untyped penalties all apply); `PF2E_CONDITION_DEFS` and `conditionMods` / `adjusted` (pp. 442–447: frightened and sickened on every check and DC, clumsy on DEX/AC/Reflex, enfeebled on STR attacks and melee damage, drained on CON/Fortitude, stupefied on INT/WIS/CHA/Will, fatigued, fascinated, unconscious, off-guard −2 circumstance AC, prone −2 circumstance attacks, encumbered as clumsy 1; prone, grabbed, restrained, paralyzed, confused and unconscious give off-guard); `takeDamage` (a typed amount or `Pf2eDamagePart[]` goes through the hero's immunities, weaknesses and resistances first, p. 407; the ±1 HP steppers don't; then Shield Block up to Hardness with the shield breaking at its BT (only with the feat or a shield granting it, against physical or untyped damage, with the reaction unspent, which it spends: `shieldBlockProblem`, Player Core p. 262), temp HP, knocked out at 0 HP with dying 1 or 2 plus wounded, +1/+2 dying for damage while dying once temp HP are gone), `heal` (back from 0 ends dying and adds wounded), `recoveryCheck` (DC 10 + dying) and `heroicRecovery`; death at dying 4 less doomed; `takePersistent` (End turn: every persistent damage rolled anew and taken at once, so dying rises once, then a DC 15 flat check each, p. 445) and `assistedRecovery` (another flat check, DC 10 for apt help, once a round); healing to full HP ends bleed. The PF2e sheet (`components/sheet/Pf2eSheet.vue`) shows AC, saves, skills, class DC and Strikes after conditions (changed values in the warn colour, the reasons in a tooltip), rolls skills and saves on a click (a save against the Save DC says its degree, with the hero's upgrades), rolls Strikes against an optional Target AC (hit, miss, crit) with a ×2 crit damage button, and uses `components/pf2e/SheetConditions.vue` (chips with values) and `components/pf2e/SheetHealth.vue` (damage or heal an amount with Crit and Shield Block; dying, wounded, doomed; recovery check and Heroic Recovery). - `utils/pf2eInventory.ts`, `utils/pf2eItemUse.ts`, `components/pf2e/SheetInventory.vue` (with `ItemPicker.vue` and `RuneEtch.vue`) — the PF2e sheet's inventory. `InventoryItem.pf2e` (`Pf2eItemState`) copies an item's numbers from the data when added (`itemFromDef`), so the sheet works without the data; `qty` stays the Bulk of one, hand-written items are one stowed item of that Bulk. Bulk (Player Core p. 269: ten light items are 1, fractions dropped, negligible nothing, a thousand coins 1, carried armor 1 more, p. 271), encumbered over 5 + STR and overloaded over 10 + STR (`bulkLimits`; hand-made sheets keep `bulkLimit`), and `syncEncumbered` gives and takes the encumbered condition (`sheet.bulkEncumbered` marks the one it gave). ## Data model

Schema lives in `supabase/migrations/`; every table has RLS. Key points:

- `profiles` (public bits, role, theme, dice colour, `own_dice`) and `user_permissions` (flags, suspension, restriction reason) are separate so other players can't read someone's restrictions. Role and flags change only through `staff_*` / `admin_*` RPCs, which also write `moderation_history`.
- `characters.sheet` is JSON typed per system (`types/sheets.ts`); a trigger caps characters at 5 per user. Shared keys (`class`, `lineage`, `hp`, `hpMax`, `ac`, `initMod`, `passivePerception`) feed the `campaign_roster` RPC.
- A character joins a campaign through `campaign_members.character_id`.
- `messages.recipient_ids` null = whole party; otherwise a secret message to those users. `messages.kind` is `'chat'` (typed) or `'action'` (rolls and casts the quick-action panel posts; the chat shows them as a compact log row only when the viewer turns on "Battle log" (off by default, remembered per browser); they raise no notifications and the dashboard skips them).
- NPCs: `npcs` is the shared pool (official + approved homebrew); only staff write it. Players suggest entries through `npc_submissions` (pending → approved/rejected via the `staff_approve_npc_submission` / `staff_reject_npc_submission` RPCs). `campaign_npcs` are a campaign's own copies and never reach the pool on their own.
- Policy helpers live in the `private` schema (`is_staff`, `can`, `is_campaign_member`, `is_campaign_gm`).
- `hero_effects`: a status one hero gives another (Help → "Helped"). Sheets don't reload while open, so the helper never writes the target's sheet: `composables/useHelpAlly.ts` inserts the row, and the target's own sheet or board panel (`useHeroEffects`) adds the status and deletes it, live or on next load. Members insert for heroes seated in their campaign; only the target's owner reads and deletes.
- Battle board: `combatants.conditions`, `actions_max` and `actions_used` hold a combatant's conditions and action pips; `campaign_initiative()` gives players the conditions but null action counts. `campaign_hero_card` is a members-only RPC returning a hero's public subset for the stats dialog; `campaign_roster`'s summary also carries `abilityNames` (for `turnActionsFor`).
- `hero_hp_changes`: an HP change the GM makes to a hero (mirrors `hero_effects`). The GM inserts through `useSendHeroHp`; only the owner reads and deletes. The hero's own sheet or board (`useHeroHpChanges`) applies it with `takeDamage` / heal and claims it by deleting the row first, so it applies once; `utils/heroHpChange.ts`, `tests/heroHpChange.test.ts`
- `hero_condition_changes`: a condition the GM adds to or removes from a hero (stats modal, `useSendHeroCondition`). The `gm_set_hero_condition` RPC writes the saved sheet at once (so it holds while the player is away) and leaves the row for an open sheet, which `useHeroConditionChanges` applies live with `addCondition` / `removeCondition` (a no-op when it matches; only the last change per condition); `utils/heroConditionChange.ts`, `tests/heroConditionChange.test.ts`
- Initiative (`encounters`, `combatants`) is GM-only; a player moves only their own seated hero and its summons with `set_my_initiative` (security definer). `encounters.initiative_mode` is the campaign's rules (GM toggle in the battle board's ⋯ menu, a select on the old tracker): `nimble` puts heroes first and lets the roll set their starting actions, `classic` orders by the roll and starts heroes with full actions (`useCampaignEncounter` → `sheet.classicInitiative`, read by `initiativeRoll`); `sortOrder(rows, mode)` applies it. Add party seats heroes with `initiative_rolled = false` ("–", top of the order) until `set_my_initiative` or the GM sets it. `useCampaignEncounter` also tells every sheet editor whether its hero is seated: being seated runs New encounter on the sheet (it then asks for Initiative), leaving the tracker runs End encounter (`seatChange` in `utils/turnSteps.ts`), and while seated (`editor.gmEncounter`) the player's steps are only Roll Initiative, Start turn and End turn.
- Lore Master context is chosen in the Edge Function from the caller's `campaign_members.role`: a GM gets the campaign (roster, sheets, NPCs, journal); a player gets only their own character, so campaign secrets never reach a player's prompt.
- Free Lore Master allowance: `ai_free_usage` (one row per user per UTC day, users read their own). Only the service role calls `use_free_ai` (atomic take, returns questions left or -1) and `refund_free_ai` (when the provider call fails); admins set the cap with `admin_set_free_ai_limit`.
- `analytics_events`: usage events (view / click / time) per user, surface, seat and viewport. RLS on with no policies: clients insert only through `track_events` (at most 300 events per user per minute; no-op while `site_settings.analytics_enabled` is off, the "Usage analytics" switch in Site features), staff read totals only through `staff_analytics_surfaces` / `_splits` / `_daily` / `_buttons` (staff accounts excluded unless asked); `staff_analytics_prune` drops events older than 180 days when the page opens; admins can wipe everything with Reset analytics (`admin_reset_analytics`, confirmed in a dialog, logged to `moderation_history`).
- Storage buckets: `portraits` (public), `campaign-files` (`{campaign_id}/…`, members only), `library` (`{user_id}/…`, any signed-in user can read).

## Linting

Dual linter setup — both must pass:

Prettier is the source of truth for formatting (2 spaces, no semicolons, single quotes, width 100) and disables conflicting ESLint rules via `eslint-config-prettier`.
